# Rust `no_std` 固定容量环形缓冲区学习笔记

## 1. 整体设计

`HistoryBuffer<T, const N: usize>` 是固定容量环形缓冲区：存储空间内嵌在结构体中，不依赖堆分配；容量满时，`push` 会移除最老元素再写入新元素。

```rust
pub struct HistoryBuffer<T, const N: usize> {
    buf: [MaybeUninit<T>; N],
    head: usize, // 下一个写入位置
    tail: usize, // 最老元素位置，即下一个读出位置
    len: usize,  // 当前有效元素数
}
```

对 `N > 0`，核心不变量为：

- `0 <= len <= N`
- `head < N` 且 `tail < N`
- `head == (tail + len) % N`（数学意义上的加法；实现时需避免整数溢出）
- 从 `tail` 开始沿环前进的 `len` 个槽位恰好包含有效的 `T`；其余槽位不得作为 `T` 读取。

## 2. 栈、`static` 与 `.bss`

- 局部 `HistoryBuffer` 通常存放在栈上，实际位置可能受编译器优化影响。
- `static` 声明的是具有整个程序生命周期的静态存储对象，并不等同于 `.bss`。
- `.bss` 通常存放零初始化的静态数据；`.data` 通常存放具有非零初值的可写静态数据；实际放置由编译器、链接器及目标平台决定。
- `MaybeUninit::uninit()` 不承诺底层字节全为零，所以不能仅凭 `new()` 断言对象一定在 `.bss`。
- `static` 对象如需调用 `push(&mut self, ...)`，应采用适合平台的内部可变性与同步机制；不能直接从普通 `static` 取得可变引用。

## 3. `const fn` 与内联 `const` 表达式

```rust
pub const fn new() -> Self {
    Self {
        buf: [const { MaybeUninit::uninit() }; N],
        head: 0,
        tail: 0,
        len: 0,
    }
}
```

- `static` 的初始化表达式必须可在编译期求值，因此其中调用的构造函数需要支持常量求值（如 `const fn`）。
- `const fn` **可以**在编译期执行，但在普通运行时代码中调用时不保证一定编译期执行。
- `[expr; N]` 对非 `Copy` 类型通常不能直接重复同一运行时值。
- `[const { MaybeUninit::uninit() }; N]` 使用内联常量表达式初始化每个槽位，不要求 `T: Copy`。

## 4. `MaybeUninit<T>` 与内存布局

`MaybeUninit<T>` 表示预留了能存放 `T` 的内存，但其中可能尚不存在有效的 `T`。

Rust 保证：

```rust
size_of::<MaybeUninit<T>>() == size_of::<T>()
align_of::<MaybeUninit<T>>() == align_of::<T>()
```

因此可以把槽位指针转换成 `*const T` 或 `*mut T`：

```rust
self.buf.as_ptr().add(index).cast::<T>()
```

但**指针转换不会初始化对象**。只有已经写入有效 `T`、且尚未被移走的槽位才能按 `T` 读取或借用。`MaybeUninit<T>` 被析构时也不会自动析构其中的 `T`。

## 5. `#[inline]`

`#[inline]` 提示编译器考虑将函数调用展开到调用处，适用于 `slot()`、`slot_mut()` 这样短小且频繁调用的辅助函数。

- `#[inline]` 不保证内联。
- 不写 `#[inline]` 也可能被优化器内联。
- `#[inline(always)]` 是更强的建议，`#[inline(never)]` 建议不要内联。
- 是否内联与内存安全无直接关系。

## 6. 核心方法与安全条件

### `slot()` / `slot_mut()`

返回指定槽位的裸指针。调用方必须保证索引在范围内；若要解引用，还必须保证该槽位已初始化并满足引用有效性、对齐和别名规则。

### `push(value)`

1. 若已满，先 `pop()` 最老元素并析构它。
2. 用 `ptr::write()` 将新 `T` 写入当前 `head` 槽位。
3. `head` 前进，`len += 1`。

`ptr::write()` 不读取或析构目标位置的旧值，所以写入前必须保证该槽位不再拥有有效的旧元素。

### `pop()`

1. 若为空，返回 `None`。
2. 用 `ptr::read()` 从 `tail` 移出一个 `T`。
3. `tail` 前进，`len -= 1`。
4. 返回 `Some(value)`。

`ptr::read()` 不会自动析构源位置；它将值移出后，源槽位必须被视为不再含有有效 `T`，避免重复读取或析构。

### `peek()`

在非空时，返回 `tail` 所指元素的 `&T`，不转移所有权。安全性依赖槽位确实已初始化；共享借用期间，安全 Rust 的借用规则阻止对同一缓冲区进行冲突的可变操作。

### `iter()`

遍历逻辑顺序而不是物理数组顺序。第 `i` 个元素的槽位为：

```rust
(self.tail + i) % N
```

要求 `i < len`、`N > 0`，且计算不能溢出。迭代器借用 `&self`，返回 `&T`。

例如物理数组 `[50, 20, 30, 40]`，`tail = 1`、`len = 4`，遍历顺序为 `20, 30, 40, 50`。

## 7. 为什么需要实现 `Drop`

```rust
impl<T, const N: usize> Drop for HistoryBuffer<T, N> {
    fn drop(&mut self) {
        while self.pop().is_some() {}
    }
}
```

`MaybeUninit<T>` 不会自动析构已经写入的 `T`，因此缓冲区需要主动清理剩余有效元素。

`pop()` **本身不会析构**返回的 `T`：它将所有权转移到 `Option<T>`。在 `self.pop().is_some()` 中，`is_some()` 只是借用临时 `Option<T>`；表达式结束后临时值被自动析构，其中的 `T` 随之被析构。

更直观的等价写法：

```rust
while let Some(value) = self.pop() {
    drop(value);
}
```

## 8. `Iterator`、`IntoIterator` 与 `ExactSizeIterator`

| Trait | 作用 | 核心接口 |
|---|---|---|
| `Iterator` | 定义逐个产生元素的方式 | `next()` |
| `IntoIterator` | 将对象转换成迭代器，使其支持 `for` | `into_iter()` |
| `ExactSizeIterator` | 保证能精确报告剩余元素数 | `len()`，依赖准确的 `size_hint()` |

- `HistoryIter<'a, T, N>` 实现 `Iterator<Item = &'a T>`，每次 `next()` 读取下一个逻辑槽位。
- 为 `&HistoryBuffer<T, N>` 实现 `IntoIterator`，便可使用 `for x in &buf`，不会消费缓冲区。
- `ExactSizeIterator` 要求 `size_hint()` 准确返回 `(remaining, Some(remaining))`。
- `buf.len()` 是缓冲区内元素总数；`iter.len()` 是迭代器剩余元素数。
- 已实现 `Iterator` 的类型自动拥有标准库提供的 `IntoIterator` 实现，因此不必再单独为 `HistoryIter` 手写该实现。

可简化重复代码，让 `iter()` 返回已有的 `HistoryIter`：

```rust
pub fn iter(&self) -> HistoryIter<'_, T, N> {
    HistoryIter { buf: self, index: 0 }
}
```

## 9. 原实现需要注意的问题

### 零容量 `N = 0`

原 `push()` 在容量为零时仍会尝试写入槽位 0，存在越界写入和未定义行为风险。可以在开头处理：

```rust
if N == 0 {
    return; // value 正常析构
}
```

### 索引加法溢出

`(head + 1) % N`、`(tail + 1) % N` 和 `(tail + i) % N` 在极端容量下可能溢出。对 `N > 0`，前进一个槽位可改成：

```rust
fn next_index(index: usize) -> usize {
    if index == N - 1 { 0 } else { index + 1 }
}
```

迭代器也可以维护当前槽位并逐步前进，避免直接计算 `tail + i`。

### 测试建议

- 空缓冲区 `pop()`、`peek()`。
- 容量为 1、容量为 0。
- 写满、覆盖、回绕和逻辑遍历顺序。
- 非 `Copy` 类型的析构计数，验证覆盖和缓冲区销毁时不会泄漏或重复析构。
- 使用 `cargo +nightly miri test` 检查可检测的未定义行为；Miri 不能代替完整的安全性证明。

## 10. 核心结论

1. `MaybeUninit<T>` 负责提供内存空间，**不负责追踪有效元素**；有效性由缓冲区不变量维护。
2. `ptr::write()` 把值写入槽位，`ptr::read()` 把值移出槽位；二者不会自动析构旧值。
3. `Drop` 必须清理仍有效的元素；`pop()` 的返回值何时析构取决于其所有权和生命周期。
4. `unsafe` 可以封装在安全 API 内部，但必须保证所有公开操作在边界条件下仍维持不变量。
5. 固定数组内嵌存储使其适合 `no_std`，但放在 `static` 中时仍需解决可变访问的同步问题。
