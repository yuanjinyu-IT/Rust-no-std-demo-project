# Rust `Display`、`Write` 与 `write!` 学习笔记

## 1. `fmt::Display` 和 `fmt::Write`

两者都属于 `core::fmt`，但职责不同：

| | `fmt::Display` | `fmt::Write` |
|---|---|---|
| 作用 | 定义一个值如何格式化为文本 | 定义文本写入哪里 |
| 实现对象 | 被格式化的类型 | 接收字符串的类型 |
| 核心方法 | `fmt()` | `write_str()` |
| 示例 | `CapacityError` | `FixedString<N>` |

### Display：值如何显示

```rust
impl fmt::Display for CapacityError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str("fixed-capacity string is full")
    }
}
```

实现 `Display` 后，可以使用 `{}` 格式化该类型：

```rust
write!(&mut out, "error: {}", CapacityError)?;
```

`fmt()` 不返回字符串，而是通过 `Formatter` 输出格式化内容。`{}` 使用 `Display`，`{:?}` 使用 `Debug`。

### Write：文本写到哪里

```rust
impl<const N: usize> fmt::Write for FixedString<N> {
    fn write_str(&mut self, s: &str) -> fmt::Result {
        self.push_str(s).map_err(|_| fmt::Error)
    }
}
```

`fmt::Write` 主要包含三个方法（简化）：

```rust
trait Write {
    // 必须实现
    fn write_str(&mut self, s: &str) -> fmt::Result;

    // 默认实现
    fn write_char(&mut self, c: char) -> fmt::Result;

    // 默认实现
    fn write_fmt(&mut self, args: fmt::Arguments<'_>) -> fmt::Result;
}
```

通常只需要实现 `write_str()`，就能获得默认的 `write_fmt()`，进而支持 `write!`。

## 2. `write!` 如何连接 Display 与 Write

```rust
use core::fmt::Write as _;

let mut out = FixedString::<64>::new();
write!(&mut out, "error: {}", CapacityError).unwrap();
```

概念调用关系：

```text
write!
  └── Write::write_fmt()
        ├── Display::fmt()       // 格式化 CapacityError
        │     └── Formatter 输出文本
        └── Write::write_str()   // 写入 FixedString
              └── push_str()
```

这只是概念示意，并非严格的宏展开或固定调用次数。`write!` 可能分多次调用 `write_str()`，不必先生成完整的 `String`。

```rust
write!(&mut out, "x = {}", 42)
```

概念上类似：

```rust
out.write_fmt(format_args!("x = {}", 42))
```

`format_args!` 构造 `fmt::Arguments`，无需创建堆分配的 `String`。

## 3. `use fmt::Write as _;`

```rust
use core::fmt::Write as _;
```

作用：**将 Trait 引入作用域参与方法解析，但不引入名为 `Write` 的绑定。**

`write!` 需要解析目标上的 `write_fmt()`，该方法由 `fmt::Write` 提供。普通导入 `use core::fmt::Write;` 也可以；`as _` 能避免与其他同名 Trait（如 `std::io::Write`）产生名称冲突。

### Trait 方法调用

**方法调用语法**（通常需要导入 Trait）：

```rust
use core::fmt::Write as _;

out.write_str("hello")?;
out.write_fmt(format_args!("x = {}", 42))?;
```

**完全限定语法（UFCS）**（无需导入 Trait）：

```rust
fmt::Write::write_str(&mut out, "hello")?;
fmt::Write::write_fmt(&mut out, format_args!("x = {}", 42))?;
```

UFCS 还可以明确指定调用哪个 Trait 的方法。

## 4. `write_report()` 关键逻辑

```rust
pub fn write_report<const N: usize>(
    out: &mut FixedString<N>,
    values: &[u64],
) -> Result<(), CapacityError> {
    use fmt::Write as _;

    let mut first = true;

    write!(out, "values: ")
        .map_err(|_| CapacityError)?;

    for v in values {
        write!(out, "{}{v}", if first { "" } else { ", " })
            .map_err(|_| CapacityError)?;
        first = false;
    }

    write!(out, " | sum = {}", values.iter().sum::<u64>())
        .map_err(|_| CapacityError)
}
```

- `out: &mut FixedString<N>`：输出缓冲区由调用者提供，无需在函数内创建 `String`。
- `use fmt::Write as _;`：使 `write!` 可以解析 `write_fmt()`。
- `first`：控制第一个元素前不写分隔符，其余元素前写 `", "`。
- `"{}{v}"`：`{}` 使用显式传入的参数，`{v}` 捕获作用域中的 `v`。
- `.map_err(|_| CapacityError)?`：把 `fmt::Error` 转换为 `CapacityError`，失败时提前返回。
- 最后一条 `write!` 不加 `?`：转换后的 `Result<(), CapacityError>` 直接作为函数返回值。

输入 `&[10, 20, 30]`，输出：

```text
values: 10, 20, 30 | sum = 60
```

**注意：** 单次 `push_str()` 容量不足时不会修改缓冲区，但整个 `write!` 可能分多次写入。`write_report()` 返回错误时，缓冲区可能留下部分内容，并不保证整体原子性。

## 5. 总结

| 概念 | 职责 |
|---|---|
| `Display` | 值如何表示成文本 |
| `Write` | 文本写到哪里 |
| `write!` | 组织格式化并写入目标 |
| `format_args!` | 构造格式化参数 |
| `Formatter` | 处理格式化选项并输出文本 |

**一句话：`Display` 决定怎么显示值，`Write` 决定写到哪里，`write!` 将两者连接起来。**

补充：`core::fmt::Write` 处理 UTF-8 文本格式化；`std::io::Write` 处理字节 I/O。`FixedString` 使用前者，适合 `no_std` 下的固定容量格式化输出。
